# 项目完整执行清单总结

本项目从零开始搭建，共分为 5 个核心阶段（Phase）。每个阶段依次递进，最终组合成一个完整的 Agentic RAG（具备智能体特性的检索增强生成）系统。

以下是项目开发过程中严格执行的完整任务清单总结：

---

## Phase 0: 环境基建 (基础设施搭建)
**目标**：为项目打好底层的代码骨架，配置好依赖环境和全局工具。

1. **创建项目骨架与依赖文件**
   - 初始化了所有目录及其对应的 `__init__.py`。
   - 编写了 `environment.yml` 和 `requirements.txt`，规定了 `streamlit`、`langchain`、`chromadb`、`loguru` 等核心依赖及其版本。
   - 创建了 `.gitignore`，防止敏感数据和日志被提交到版本控制系统。
2. **实现全局配置模块**
   - 编写 `config/settings.py`，使用 `pydantic-settings` 实现了模块级的单例配置中心。
   - 实现了自动读取 `.env` 文件中的 API 密钥、模型名称、数据库路径等参数。
3. **实现日志与工具模块**
   - 引入 `loguru` 库，在 `utils/logger.py` 中配置了控制台的彩色日志输出，并自动将日志保存到 `data/logs/app.log` 中。
   - 在 `utils/file_utils.py` 中实现了文件编码自动检测功能，防止读取中文 TXT 时出现乱码。

---

## Phase 1: 数据管线 (文档入库与检索)
**目标**：实现对用户上传文献的解析、切分，并将其转化为可搜索的向量存入本地数据库。

4. **实现文档解析器**
   - 在 `core/parser/` 下采用了工厂模式设计。
   - 实现了对 `.pdf`、`.docx`、`.txt` 等多种格式的解析，尽最大可能保留原文的层级结构。
5. **实现语义分块器**
   - 在 `core/chunker/` 中，摒弃了传统的“固定字数切分法”。
   - 通过正则表达式识别学术论文中的 `#`、`##` 等各级标题，按语义段落进行智能切分，并在切分块（Chunk）的元数据中记录所属的“章节路径”。
6. **实现 Embedding 服务**
   - 在 `core/vectorstore/embedder.py` 中，调用远端大模型的 Embedding API，将文字转化为高维向量（一串浮点数）。
   - 实现了“分批发送”和“出错自动重试”的容错机制。
7. **实现 ChromaDB 存储与检索器**
   - 接入本地向量数据库 ChromaDB。实现了文档向量的持久化写入、按文件名定点删除，以及基于余弦相似度的 Top-K 检索。
   - 编写了 `retriever.py`，负责将检索到的零散片段格式化为带有 `[1]`、`[2]` 引用编号的连贯上下文。

---

## Phase 2: 对话与 RAG 引擎 (大模型核心控制流)
**目标**：这是系统最具备“智能”的大脑部分，实现了自我裁判和多轮重试机制。

8. **实现 LLM 客户端**
   - 封装了兼容 OpenAI 标准接口的 `LLMClient`，支持打字机效果的“流式输出（Streaming）”以及随时可以被用户打断的功能。
9. **实现 Prompt 模板中心**
   - 在 `config/prompts.py` 中集中编写了极具约束力的系统提示词。要求大模型绝对不能产生“幻觉（胡编乱造）”，并且强制要求回答必须标注参考文献来源。
10. **实现 LLM-as-a-Judge 裁判模块**
    - 在 `core/rag/judge.py` 中，引入了创新的裁判机制。模型会对自己写的“草稿”从“事实一致性”和“完整性”两个维度进行打分，并输出 JSON 格式的评估结果和改进建议。
11. **实现查询重写器**
    - 在 `core/rag/query_rewriter.py` 中，解决了多轮对话的指代不清问题。如果用户追问“它的缺点是什么？”，该模块会结合前文将其重写为“MAPF算法的缺点是什么？”后再去数据库搜索。
12. **实现 Agentic 核心控制流**
    - 在 `core/rag/agent.py` 中，用一个 `while` 循环将上述所有组件串联起来：
      **重写问题 -> 检索数据库 -> 写草稿 -> 裁判打分 -> (如果分数低则根据建议重试 / 如果分数高则停止思考并流式输出最终答案)**。

---

## Phase 3: 对话持久化 (历史记录管理)
**目标**：将会话内容保存到本地，以便用户下次打开软件时能继续之前的研究。

13. **实现对话存储层**
    - 定义了 `Message` 和 `Conversation` 的数据结构。
    - 在 `core/conversation/storage.py` 中，将每一个对话会话序列化为 JSON 格式，保存在本地的 `data/conversations/` 目录下。
14. **实现会话管理器与智能标题生成**
    - 在 `core/conversation/manager.py` 中提供了增删改查对话历史的统一接口。
    - 当用户发起一段新对话的第一个问题后，后台会调用轻量级大模型，自动将这轮问答总结为一个不超过 6 个字的简短标题（如“自动驾驶强化”）。

---

## Phase 4: Streamlit 前端 (可视化网页界面)
**目标**：将所有强大的后台逻辑包装进一个对用户友好、美观的网页应用中。

15. **实现 State 状态管理**
    - 在 `ui/state.py` 中管理页面的全局状态，确保在页面刷新、组件交互时，当前的聊天记录、正在生成的锁定状态等数据不会丢失。
16. **实现自定义样式**
    - 在 `ui/styles.py` 中注入了 CSS 代码，隐藏了 Streamlit 原生界面中不需要的菜单和水印，美化了聊天输入框和“停止生成”按钮。
17. **实现侧边栏与历史会话组件**
    - 在 `ui/components/sidebar.py` 中，构建了左侧导航栏。用户可以在这里一键创建新对话、点击切换历史对话、查看并管理本地知识库中已收录的文献。
18. **实现文件上传组件**
    - 在 `ui/components/file_uploader.py` 中，实现了支持多文件拖拽的上传区。配合进度条组件，向用户直观展示“读取 -> 解析 -> 分块 -> 向量化入库”的全过程。
19. **实现主聊天区域与状态展示**
    - 在 `ui/components/chat_area.py` 中，渲染类似 ChatGPT 的对话气泡。
    - 在用户提问后，调用后端的 Agentic RAG 引擎。同时在界面上渲染一个名为“🧠 AI 正在深度思考...”的可折叠状态框，实时向用户汇报后台的检索、草稿生成和裁判打分进度。
20. **实现主入口并解决导入路径问题**
    - 在 `ui/app.py` 中组装了所有的 UI 组件。通过在脚本顶部动态向 `sys.path` 中插入项目根目录的绝对路径，彻底解决了终端启动 Streamlit 时常见的 `ModuleNotFoundError` 模块找不到的问题。
