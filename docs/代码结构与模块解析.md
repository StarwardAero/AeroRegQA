# 核心代码结构与模块详细解析

本文档旨在详细解释本系统的目录结构以及各个代码模块的具体功能。内容采用专业且易于理解的技术语言，适合希望了解系统底层逻辑或进行二次开发的开发者阅读。

---

## 整体目录结构

系统代码按照功能划分为多个层级，遵循高内聚、低耦合的设计原则。

```text
academic-rag-system/
|-- .env                        # 环境变量配置文件（存放 API 密钥等敏感信息）
|-- requirements.txt            # Python 依赖包清单
|-- config/                     # 配置中心目录
|-- core/                       # 核心业务逻辑目录（解析、分块、向量库、RAG引擎、会话管理）
|-- data/                       # 本地数据持久化目录（自动生成，存放上传的文件、向量库文件、JSON聊天记录等）
|-- ui/                         # Streamlit 前端界面目录
|-- utils/                      # 通用工具函数目录
```

---

## 各模块功能详述

### 1. 配置中心 (`config/`)

- **`settings.py`**：全局配置加载器。利用 `pydantic-settings` 库自动读取 `.env` 文件中的环境变量。它集中定义了项目中的各种绝对路径、模型名称、温度参数（Temperature）、检索数量（Top K）和裁判阈值等，并将自身实例化为一个单例对象供全局调用。
- **`prompts.py`**：提示词（Prompt）管理中心。大语言模型（LLM）需要明确的指令才能执行特定任务。该文件集中存放了四种核心提示词模板：
  1. **基础问答提示词**：要求模型严格基于给定的上下文进行回答，并标注来源编号。
  2. **裁判评估提示词**：要求模型对生成的草稿进行打分，并返回 JSON 格式的评估结果。
  3. **查询重写提示词**：用于处理多轮对话中的指代消解问题（如将“它的缺点是什么”补全为具体的主语）。
  4. **标题生成提示词**：用于给历史对话自动起名。

### 2. 核心业务逻辑 (`core/`)

这是系统的底层引擎，分为五个子模块。

#### 2.1 文档解析模块 (`core/parser/`)
负责将用户上传的非结构化文件（PDF, DOCX, TXT）提取为纯文本或 Markdown 格式。
- **`base.py`**：定义了解析器的抽象基类 `BaseParser`，规范了所有具体解析器必须实现 `parse()` 方法。
- **`pdf_parser.py`**：PDF 解析器。实现了降级处理机制：优先尝试使用 `marker-pdf` 库（能够较好地保留数学公式和版式），若未安装或报错，则平滑降级使用 `PyMuPDF` 进行基础的文本提取。
- **`docx_parser.py`**：Word 文档解析器。利用 `python-docx` 读取段落，并将标题样式转换为 Markdown 的 `#` 语法。
- **`txt_parser.py`**：纯文本解析器。内置了 `chardet` 编码检测，防止读取包含中文字符的文本文件时出现乱码。
- **`parser_factory.py`**：工厂模式实现。根据文件后缀名自动分配对应的解析器实例。

#### 2.2 语义分块模块 (`core/chunker/`)
将长篇大论的文档切割成适合向量化和检索的小块（Chunks）。
- **`chunk_models.py`**：定义了 `DocumentChunk` 数据类，包含文本内容（content）、元数据（metadata）和唯一标识符（chunk_id）。
- **`semantic_chunker.py`**：语义分块器。它不采用简单的固定字数切分，而是利用正则表达式识别 Markdown 中的 `H1/H2/H3` 标题，将文档按章节进行切分，并在切分块的元数据中记录“章节路径”（例如 `Introduction > Details`）。对于超长章节，再使用 LangChain 的递归字符切分器进行二次切分，并保留重叠字符（Overlap）以防止上下文断裂。

#### 2.3 向量存储与检索模块 (`core/vectorstore/`)
负责文本的向量化运算、本地持久化存储以及相似度计算。
- **`embedder.py`**：向量化服务。调用远端 API 将文本转换为高维浮点数向量。内置了分批处理机制（防止请求体过大）和指数退避重试机制（防止网络偶尔超时导致整体失败）。
- **`chroma_store.py`**：数据库操作封装。使用本地化的 ChromaDB 作为向量数据库。实现了数据的添加、指定文件删除、统计和基于余弦相似度的检索功能。所有数据存储于本地 `data/chroma_db` 目录。
- **`retriever.py`**：高级检索器。除了执行数据库查询外，还负责将查询到的零散文本块格式化为带有引用编号的连贯字符串，供大模型阅读。

#### 2.4 Agentic RAG 引擎 (`core/rag/`)
系统最核心的大脑，控制“思考-打分-重试”的循环逻辑。
- **`llm_client.py`**：统一的大模型客户端封装。支持标准的非流式请求，以及带有回调函数和外部中断信号支持的流式请求。
- **`query_rewriter.py`**：利用较轻量级的模型，将用户当前的简写提问结合最近几轮的对话历史，重写为完整的检索语句。
- **`judge.py`**：LLM 裁判模块。让模型扮演评委，对它自己生成的草稿根据“事实一致性”和“完整性”进行打分，并解析其返回的 JSON 数据。
- **`agent.py`**：核心控制流。实现了一个 `while` 循环：重写查询 -> 数据库检索 -> 生成非流式草稿 -> 裁判打分。如果得分低于阈值，将裁判给出的建议补充进查询条件，重新进入下一轮循环；如果得分合格或达到最大循环次数，则退出循环，以流式形式向用户输出最终答案。

#### 2.5 会话持久化模块 (`core/conversation/`)
负责管理多轮聊天的历史记录。
- **`models.py`**：定义了 `Message` 和 `Conversation` 的数据结构，提供了与 Python 字典（Dict）相互转换的方法。
- **`storage.py`**：文件系统操作类。将每个对话保存为独立的 JSON 文件，存储于 `data/conversations/` 目录下。
- **`title_generator.py`**：调用轻量级模型，提取首轮问答的核心语义，生成不超过6个字的短标题。
- **`manager.py`**：提供给前端调用的统一接口层。负责创建会话、添加消息记录、读取历史上下文供大模型使用等。

### 3. 前端界面 (`ui/`)

使用 Streamlit 框架构建的可视化网页端。
- **`app.py`**：程序主入口。负责全局页面的配置、依赖服务的单例初始化，并组装侧边栏和主区域。在文件顶部处理了 `sys.path` 路径问题，确保模块导入正常。
- **`state.py`**：状态管理器。封装了 `st.session_state` 的读写操作，用于在多次页面刷新之间保持数据（如当前选择的会话 ID、打断事件对象等）的持久化。
- **`styles.py`**：自定义 CSS 样式注入。通过注入 HTML `<style>` 标签，覆盖 Streamlit 的默认样式，实现如隐藏页脚、优化按钮样式、添加“思考中”动画等视觉效果。
- **`components/`**：
  - **`sidebar.py`**：侧边栏组件。渲染模型选择下拉框、新建会话按钮、历史对话列表列表及知识库文档管理功能。
  - **`file_uploader.py`**：文件上传组件。处理多文件拖拽上传，并提供实时的解析、分块、入库进度条展示。
  - **`status_display.py`**：状态展示组件。以可折叠的日志形式，向用户展示 Agent 引擎在后台执行“重写-检索-草稿-裁判”等各个步骤的耗时及详情。
  - **`chat_area.py`**：聊天交互区。渲染历史消息气泡，处理用户输入，调用后端的 Agentic RAG 引擎，并通过回调函数实时流式更新界面内容。

### 4. 工具模块 (`utils/`)
- **`logger.py`**：利用 `loguru` 库配置全局日志系统，实现控制台彩色输出与日志文件滚动保存。
- **`file_utils.py`**：包含安全保存上传文件、清理临时文件以及利用 `chardet` 库进行文件编码推断的工具函数。
- **`text_utils.py`**：文本清洗工具，包含去除空字符、截断字符串以及将 LaTeX 公式标准化等功能。
